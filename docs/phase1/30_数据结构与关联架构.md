# Phase 1E 数据结构与关联架构

## 证据层级

| 数据层 | 当前定位 | 可用分析边界 |
|---|---|---|
| 学生问卷 | PRIMARY | 研究经历、AI协作事实、自报行为、情境策略及背景的分项描述 |
| 学生短任务 | SECONDARY PERFORMANCE EVIDENCE | 全体任务参与者的六维分项表现；不合成能力总分 |
| 学生/教师访谈 | SECONDARY QUALITATIVE EVIDENCE | 获批后用于补充过程解释，不估总体比例 |
| 企业岗位画像 | SUPPLEMENTARY DEMAND-SIDE EVIDENCE | 仅在获得真实数据与许可后做多标签岗位结构描述 |

Phase 1F 合成 schema/CSV 仍保留六维旧模拟字段以维护既有流程可复现；Phase 1G 当前评分设计是 v0.5 五维候选，未冻结。两者不可混作同一研究版数据合同；正式数据结构须在工具冻结后再决定是否迁移。

主路径为“AI协作方式→信息辨识与评估能力/方法理解与适配/独立研究决策能力→可观察任务表现”。其他测量与分析保持 OPTIONAL/RESERVE。

## 关系键和分析总体

模拟问卷以 `research_id` 为记录键；短任务模拟记录从问卷编号中抽取；评分长表以 `research_id+rater_id+dimension` 识别评分记录。真实方案是否关联仍为 `PENDING`，去标识化研究编号不等于匿名，批准前不得生成真实编号或映射表。

`ALL_TASK_PARTICIPANTS` 可用于任务完成、表现分布、经历和基本背景描述。只有 `AI_USER_TASK_SUBSAMPLE` 可用于追问理由、检查依据、修改/拒绝AI建议和AI协作过程变量；未使用AI不代表低AI协作能力，不得填0代替跳题。

企业岗位主键使用概念 `stable_job_record_key`。未来可能来自原生 `job_id`、平台记录ID或基于经许可字段构造的组合键；必须依据实际数据确定，不在本阶段冻结。

## 缺失码

`NA_SKIP` 为结构性跳题，`NA_APPL` 为不适用，`NA_DK` 为不知道/记不清，`NA_MISS` 为应答漏答，必要时 `NA_REFUSE` 为拒答。有效回答“未使用/无经历/未遇到”与缺失码区分。模拟流程检验上述类别不会被统一转为空白或0。
# Phase 2B 补充：v0.6候选数据字段

问卷题号和字段以v0.6候选为准；v0.5是历史版本。模拟Schema与Python流程仅用于软件检查，不能作为已冻结调查表或真实数据模板。

| 模块 | 字段/关系 | 规则 |
|---|---|---|
| 调查记录 | `research_id`、Q1经历状态、Q4专业大类、年级、训练经历 | Q1的资格门槛待导师确认；尚未确认时不得按经历状态筛除 |
| Q10核查 | `ai_evidence_checked`、`ai_evidence_objects`、`ai_evidence_methods` | 核查过/未核查/无相关输出/不知道/拒答/漏答分开；仅核查过时展示对象、方式；子项自身也支持不知道、拒答、漏答及结构跳题 |
| Q13行为 | `info_source_check_actions` | 去重多选；通常无特别核查、没有相关经历、不确定、拒答、漏答分别编码，均与具体行为及彼此互斥 |
| Q14方法 | `method_choice_occurred`、`method_decision_actions`、`ai_method_compare` | 本人选择可在未用AI时发生；AI比较在Q7=使用过时展示，独立于本人是否涉及方法选择 |
| Q16需求 | `training_need` | 全体展示、最多3项；无额外需求/未知/拒答互斥 |
| 任务、访谈、招聘 | survey-task以获批随机研究编码关联；访谈与调查默认不直接合并；岗位文本独立来源表 | 关联方式、匿名风险、来源许可与保存安排待审批，不保存身份映射于分析表 |

字段契约、缺失码及跳题见[`问卷v0.6变量字典`](instruments/06_questionnaire_variable_dictionary_v0_6.md)与[`v0.6跳题表`](instruments/08_questionnaire_skip_tree_v0_6_candidate.md)。模拟Schema和生成器覆盖Q1–Q20的候选字段；平台中立导入原型目前只转换Q1/Q2/Q3/Q7，不可视为完整导入器。Q8六类行为与现有四个阶段变量的合并/未覆盖边界见问卷正文，不得声称完全可区分。真实表单字段只有导师确认且获批后才可冻结。当前无真人数据。
