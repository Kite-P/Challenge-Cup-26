# 仓库文档状态规范

## 用途

本规范用于区分仓库材料的版本和可用范围，不构成伦理审查、导师批准、法律判断或实施授权。不要为统一格式而大规模移动文件；更新链接时保留历史文件。

## 状态标签

| 标签 | 含义 | 可否据此实施 |
|---|---|---|
| `ACTIVE_CANDIDATE` | 当前用于内部审阅和后续决策的候选材料 | 否，除非另有明确审批和授权 |
| `HISTORICAL` | 保留早期版本、旧术语、已被后续状态取代的记录 | 否 |
| `REFERENCE` | 方法、来源或规则参考材料 | 否 |
| `SYNTHETIC_ONLY` | 仅用于合成数据、软件流程或格式测试 | 否，不是真人证据 |
| `PENDING_APPROVAL` | 等待导师、机构或适用程序审阅 | 否 |
| `PENDING_OFFICIAL_RULES` | 等待适用于本届/本周期的正式竞赛规则或通知 | 否 |
| `DEPRECATED` | 不再作为当前入口，因兼容和历史追溯而保留 | 否 |

文档可以同时具有内容状态和伦理/实施状态；若有冲突，以更严格的“未获批准/不得实施”状态为准。日期、样本和状态只能按可追溯证据更新。

## 项目状态与文档状态分开

`PILOT_BLOCKED` 是项目实施门禁，不是文档标签。技术测试通过、方案材料齐备或赛事方向确认均不能自动解除该门禁。若没有得到正式审批、渠道许可和工具授权，继续标记 `PILOT_BLOCKED`。

## 版本入口规则

活跃索引应为每个研究组件指定一个内部审阅入口，并同时列出对应状态、版本、替代关系和实施限制。旧版保留在原路径，不冒充当前版本。
